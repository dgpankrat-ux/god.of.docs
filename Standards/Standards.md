# Стандарты и стайлгайды

Формальные стандарты (ISO/IEEE/ГОСТ) и официальные стайлгайды крупных компаний — нормативные документы, на которые стоит опираться при написании технической документации.

## 2022

- **[Google Developer Documentation Style Guide: Procedures](https://developers.google.com/style/procedures)** — Раздел гугловского стайлгайда с рекомендациями по написанию пошаговых инструкций (процедур) в технической документации.
- **[Command Line Interface Guidelines](https://clig.dev/)** — Свод рекомендаций по проектированию UX командной строки — полезен при документировании CLI-инструментов.
- **[Federal Plain Language Guidelines](https://www.plainlanguage.gov/guidelines/)** — Официальное руководство по простому языку для госорганов США, принятое на основе закона Plain Writing Act 2010 года, — хороший эталон ясности для технических текстов.
- **[Microsoft Writing Style Guide](https://learn.microsoft.com/en-us/style-guide/welcome/)** — Официальный стайлгайд Microsoft по стилю письма для технической документации, задающий единые правила тона, терминологии и форматирования.

## 2023

- **[Словник стоп-фраз (design.gov.ua)](https://design.gov.ua/ua/teksty-i-kontent/slovnik-stop-fraz)** — Украинский государственный стайл-гайд со списком канцеляризмов и штампов, нежелательных в UX-текстах и контенте.
- **[Пошукова оптимізація (design.gov.ua)](https://design.gov.ua/ua/teksty-i-kontent/poshukova-optimizaciya)** — Раздел государственного украинского стайл-гайда с рекомендациями по поисковой оптимизации текстов сайта.

## 2024

- **[IEEE 29148-2018 (Requirements Engineering)](https://standards.ieee.org/standard/29148-2018.html)** — Стандарт регламентирует процессы сбора и анализа требований к ПО, включая создание документа SRS.
- **[ISO/IEC/IEEE 42010-2011 (Architecture Description)](https://standards.ieee.org/standard/42010-2011.html)** — Стандарт определяет требования к описанию архитектуры системы (SAS) — структуру, точки зрения и принципы архитектурного проектирования.
- **[IEEE 1016-2009 (Software Design Descriptions)](https://ieeexplore.ieee.org/document/5167255/)** — Стандарт описывает структуру и содержание документа проектирования ПО (SDD), включая детализацию компонентов и диаграммы низкоуровневого проектирования.

## 2026

- **[Procedures and instructions — Microsoft Style Guide](https://learn.microsoft.com/en-us/style-guide/procedures-instructions/)** — Официальные рекомендации Microsoft по написанию разделов с процедурами и пошаговыми инструкциями в документации.
- **[Topic types — GitLab Documentation](https://docs.gitlab.com/development/documentation/topic_types/)** — Документация GitLab о типизации тем (концепт, задача, референс и т.д.), используемой при структурировании доков.

## Прочее

- **[ASD-STE100 — Simplified Technical English](https://www.asd-ste100.org/)** — Официальный сайт международного стандарта упрощённого технического английского (STE), обязательного во многих отраслях (авиация, оборона) и полезного как эталон ясности формулировок.
